Prototype — Goals with tasks

Throwaway mockup for agreement. Everything is local state: drag cards, add goals and tasks, press "Simulate agent cycle" to see what the AI adds.

Decisions to agree on

  1. Which layout is the default? A keeps today's goal board and folds tasks inside each card. B is a swimlane per goal (the parent is the row). C is a flat task board where every card carries its parent chip. These can be tabs of the same card.
  2. Task status = the same four lanes as goals (To do / In progress / Blocked / Done). Today tasks are only checkboxes (- task: [x] in GOALS.md); this needs a status per task and an author (you / agent).
  3. Goal status from its tasks? Proposal: the goal status stays yours/the agent's to set, but the board nudges: first task moves to In progress → goal moves to In progress; all tasks done → "mark goal done?" (shown in A). Blocked tasks never block the goal automatically.
  4. Can a task move to another goal? In B, dropping a task on another goal's row reparents it. Allow it, or restrict drag to the task's own row?
  5. Agent-created tasks flash once and carry the "agent" badge plus the cycle that created them (opens the cycle, like every Why). Should the agent be allowed to move or edit your tasks, or only its own?
  6. Can the agent close a task you created? Proposal: yes, with the cycle recorded so the Why shows it.
