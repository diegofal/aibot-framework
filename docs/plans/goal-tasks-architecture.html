Goal tasks and task workers

How tasks become the unit of work, and how a cycle hands them to workers that keep going until the task is finished while the operator watches. Revision 4: two adversarial reviews against the code reshaped it (section 7). Plan: docs/plans/goal-tasks-architecture-plan.md.

The cycle orchestrates; workers do task work. The planner breaks goals into tasks and dispatches them. Each worker works one task in persisted, bounded steps, reporting after every step, until it is done, blocked or out of budget. Everything it does carries runId + taskId; the operator sees every running worker live and can stop it.

2 · Dispatch and a worker's run

The cycle does not wait for workers. A run spans as many cycles as it needs; when it ends it wakes the cycle.

5 · Decisions

DecisionWhy
D1 Tasks in their own store (TASKS.json)Notes, claims and revisions do not fit the GOALS.md line; the completed-goals cap deletes tasks.
D2 Planner chooses, loop + pool act, worker reportsThe loop never dispatches what the planner did not name; gate, explore and idle rules apply at dispatch.
D3 Worker = in-process step loop of the same agent on a shared runExecutorTurn()Rejected: worker as a cycle variant (everything keyed by bot, strategist/planner cost per step); a long CLI session (one-shot, no resume); a separate bot (split identity, needs approval).
D4 Budgets: steps, tool calls, wall time, daily steps per botOne full-prompt call per step: an 8-step task costs ~2–3 of today's cycles. OpenClaw bounds only time and still lets runs overrun.
D5 Caps start at 1 per bot, 2 fleet-wide, global claude-cli semaphoreNothing limits CLI processes today; worker 429s must open the shared breaker.
D6 Resume from the journal, max 2 attempts; sent/executed steps never re-runResuming is safe only when side effects are known. OpenClaw finalizes instead.
D7 Permissions never block outside conversationsThe blocking path has no timeout: enforcing it as-is would stall every cycle.
D9 Socket tenant filter in phase 0Executors already stream tool events to every connected client.

6 · Phases

  1. Foundations — TaskStore + op API + both boards + goals view; socket tenant filter; real abort with fallback guards; non-blocking confirm behind a flag; runExecutorTurn(); shared breaker + claude-cli semaphore. No change to how agents plan; several live bugs fixed.
  2. Planner uses tasks — new_tasks, taskId on cycle work. Judge breakdown quality before any worker runs.
  3. Workers — 2a: pool, step loop, journal, report tools, sweep, per-task dirs, wake-on-end (no asks, no confirm tools). 2b: asks/approvals per run, shutdown + resume. Behind workers.enabled, one bot first.
  4. Live visibility — worker events, API, badges, Active workers strip, Fleet Workers view, worker sheet with Stop/Retry.
  5. Strategist and upkeep — deliverable → task, lint, karma per run, Why for tasks and runs.
