1. Module layout

The 9 files in src/productions/ split the previous monolith into single-purpose modules. The facade (service.ts) owns the side effects; the other modules are pure functions or thin I/O wrappers.

├── index.ts        5 lines  # Barrel: re-exports ProductionsService only (§6.5)

├── frontmatter.ts  246 lines  # YAML frontmatter, content quality, coherence

Total: 2,418 lines across 11 modules. The facade went from 1,573 lines to 621 (−61%). Per the plan §4.3, the original 150–200 target was unreachable at the current comment density; the chosen path is to trim historical narration and accept the ~620-line target. The remaining bulk is the public API surface (35 methods) + the karma/soul/activity side effects in evaluate that §4.1 keeps on the facade.

2. Facade composition

The C2 architecture: submodules are pure functions returning data; the facade owns the side effects. Every public method on ProductionsService is a thin wrapper that delegates to a submodule and adds the side effect (JSONL append, rebuildIndex, log line).

The linear composition for index rebuild is the load-bearing example. It demonstrates the architectural decision: the recursion that existed under the old architecture is gone.

2.1 The "no recursion" composition

src/productions/service.ts:

  // Cycle 8: linear composition. No recursive call back into rebuildIndex.
  rebuildIndex(botId: string): void {
    const dir = this.resolveDir(botId);
    const soulDir = resolve('config/soul', botId);

    const candidates = this.runCleanup(botId);
    if (candidates && candidates.length > 0) {
      const archived = this.applyArchiveBatch(dir, botId, candidates);
      if (archived > 0) {
        this.logger.info({ botId, archived }, 'Auto-cleanup completed');
      }
    }

    rebuildIndexPure(botId, dir, soulDir);
  }

The three calls do not invoke each other. runCleanup returns a list of {path, reason} candidates (or null when throttled). applyArchiveBatch moves the files and appends JSONL entries via archiveFilePure + appendEntry. rebuildIndexPure emits the index.html. The throttle on runCleanup is no longer load-bearing — the cycle does not exist.

2.2 The "pure submodule" composition

For each public method, the facade does three things: build the context, delegate to the pure function, take the side effect. Example:

src/productions/service.ts:

  getStats(botId: string): { ... } {
    const dir = this.resolveDir(botId);
    const changelogPath = join(dir, 'changelog.jsonl');
    const entries = readEntriesPure(changelogPath);    // // changelog.ts: JSONL → ProductionEntry[]
    return getStatsFromEntriesPure(entries);            // // changelog.ts: pure reduction
  }

No config checks, no logger calls, no I/O — the work is done by the pure module. The same shape applies to getChangelog, getAllEntries, getDirectoryTree, getEntry, and the read-modify-write mutations (evaluate, setCoherenceCheck, addThreadMessage, deleteProduction, deleteByPath) — they all read with readEntriesPure, mutate the in-memory array, then write with writeEntriesPure.

3. Module reference

Legend: pure = no config, no logger, no facade; I/O = thin wrappers over node:fs; mixed = pure data + I/O.

paths.ts pure

Path resolution and the single source of truth for traversal validation.

resolveDir(config, botId) → string
isTrackOnly(config, botId) → boolean
isEnabled(config, botId) → boolean
resolveFilePath(dir, entry) → string | null
assertWithinDir(dir, relativePath) → boolean

Constants: INDEX_EXCLUDES, TREE_EXCLUDES.

Called by every module that touches the filesystem (8 call sites total). The single assertWithinDir validator handles .., absolute paths, and Windows prefix-sibling bypass.

Constant: SUMMARY_FILENAME. The plan field was removed in Cycle 3 (LLM-generated plans were dropped from the payload).

The vendored marked.min.js is gone. The HTML is fully self-contained — no client-side JS, no external assets.

files.ts I/O

File operations on the production directory. Pure I/O — takes {dir} + path, returns data or moves files.

archiveFile({dir}, relPath, reason) → { ok, entry } | { ok: false }
getFileContent({dir}, relPath) → { content, size } | null
updateContent({dir}, relPath, content) → boolean
getNextNumber({dir}, relativeDir) → string
renumberFile({dir}, relPath) → string

Every function validates its path via assertWithinDir (R1 fix). The 4th skipRebuild parameter on archiveFile is gone — the recursion is broken at the composition layer.

changelog.ts mixed

JSONL read/parse/filter/stats. Pure for data, I/O for the file operations.

parseEntries(lines) → ProductionEntry[]
filterEntries(entries, {since, status, botId}) → ProductionEntry[]
sortByTimestamp(entries, order?) → ProductionEntry[]
filterApproved(entries) → ProductionEntry[]
filterRejected(entries) → ProductionEntry[]

The pure functions make the read-modify-write mutations in service.ts testable without a filesystem. filterEntries is the C4 contract (getAllEntries honors since).

tree.ts I/O

Directory walker with changelog enrichment. Reusable I/O.

walkTree({dir, entryMap, excludes}) → TreeNode[]

Called by service.getDirectoryTree after the facade builds the entry map. The walker respects TREE_EXCLUDES at every level and skips absolute-path entries (review-4 B1 fix).

service.ts facade

The public API. Every method is a thin wrapper that composes the pure modules and owns the logger/config side effects.

Public methods: logProduction, getChangelog, getEntry, getAllEntries, getStats, getStats, evaluate, setAiResponse, setCoherenceCheck, addThreadMessage, deleteProduction, deleteByPath, updateContent, getFileContent, getFileContentByPath, archiveFile, getNextNumber, renumberFile, rebuildIndex, getDirectoryTree, getAllDirectoryTrees, getAllBotStats, readActiveGoals, readSummary, writeSummary, resolveDir, isTrackOnly, isEnabled, checkCoherence, plus the static assessContentQuality, injectFrontmatter, parseFrontmatter, resolveCreatedAt, extractDescription.

Private state: lastCleanupAt (1-hour throttle for runCleanup).

6. Index rebuild flow

The end-to-end flow that demonstrates the architectural property — no recursion, linear composition:

rebuildIndex(botId)
  │
  ├─→ runCleanup(botId)→ cleanupScheduler.runCleanup
  │     │
  │     └─→ analyzeCleanup(dir, now, coherenceCheck)
  │           ├─→ reads changelog.jsonl (readEntries)
  │           ├─→ walks dir, builds hashMap
  │           └─→ returns Array<{path, reason}>
  │     │
  │     └─→ CleanupScheduler enforces 1-hour throttle
  │           (returns null if < 1h since last call)
  │
  ├─→ applyArchiveBatch(dir, botId, candidates)
  │     │
  │     └─→ for each candidate:
  │           ├─→ archiveFilePure({dir}, path, reason) → {ok, entry}
  │           ├─→ appendChangelog(path, entry)  ← writes JSONL
  │           └─→ count++
  │
  └─→ rebuildIndexPure(botId, dir, soulDir)
        │
        ├─→ walks dir, builds file list
        ├─→ buildEntryMap(dir) → Map
        ├─→ reads GOALS.md (readActiveGoalsPure)
        ├─→ buildIndexHtml(...) → string
        └─→ writeFileSync(index.html)

Under the old architecture, step 1 (runCleanup) called back into rebuildIndex at the end of the batch, which called runCleanup again. The throttle (1/hour) kept the recursion bounded — but it was a real smell. The new architecture is flat: cleanup.ts owns the analysis + throttle state together (§4.2); the facade owns the side effects (applyArchiveBatch + rebuildIndexPure, §4.1). No recursion. The order is the order.
